SQL-Labor @KIT_VERSION@ von Tobias Weber
==========================================

Portable MariaDB @MARIADB_VERSION@ (LTS) mit phpMyAdmin @PMA_VERSION@ im Browser und der
Beispieldatenbank northwind; MySQL Workbench kann sich ebenfalls verbinden.
Ein zweiter Webserver liefert eigene HTML- und PHP-Seiten aus (Webordner).
Keine Installation, keine Adminrechte, kein XAMPP. Alles lauscht nur auf
127.0.0.1: Von außen ist nichts erreichbar, jeder PC hat seine eigene
Datenbank.

Stand: Test-Kit. An einem Schul-PC (Windows 11) starten die Programme,
PHP und der Webserver; die Datenablage wird noch erprobt.


1. Benutzung (SuS)
------------------

START.bat                    Datenbank und phpMyAdmin starten, Browser
                             öffnet sich. Beim ersten Mal wird northwind
                             geladen (ca. 20 Sekunden). Die zwei minimierten
                             Fenster "SQL-Labor ..." offen lassen.
STOPP.bat                    Alles beenden. Die Daten bleiben erhalten.
NORTHWIND-ZURUECKSETZEN.bat  northwind auf den Ausgangsstand zurücksetzen
                             (fragt vorher nach).
WEB.bat                      Webordner und eigene Seiten im Browser öffnen.

phpMyAdmin im Browser: http://127.0.0.1:18080/
SQL eingeben: links northwind anklicken, oben Reiter "SQL".


2. Eigene Webseiten (HTML, PHP, MySQL)
--------------------------------------

START.bat startet einen zweiten Webserver für eigene Seiten:

  im Browser:  http://127.0.0.1:18000/
  Ordner:      Dokumente\SQL-Labor-Web   (WEB.bat öffnet ihn)

Beim ersten Start legt START.bat den Ordner mit einer Startseite (Liste der
Dateien, Test der Datenbank), hallo.html und dem PDO-Beispiel
northwind_kunden.php an. Danach fasst START.bat den Ordner nie wieder an:
Eigene Dateien werden nicht überschrieben.

- Datei hineinlegen, z. B. seite.php, im Browser aufrufen:
  http://127.0.0.1:18000/seite.php
- Unterordner ohne index.php oder index.html zeigen eine Dateiliste.
- PHP-Fehlermeldungen erscheinen im Browser (zum Lernen gewollt).
- Verbindung zur Datenbank aus PHP:
    $db = new PDO('mysql:host=127.0.0.1;port=13306;dbname=northwind;charset=utf8mb4', 'sus', 'sus');
    $db = new mysqli('127.0.0.1', 'sus', 'sus', 'northwind', 13306);
  Port 13306 nicht vergessen, 3306 ist es hier nicht.
- Anderer Ordner (z. B. auf dem Home-Laufwerk): eine Datei WEBORDNER.txt
  neben START.bat anlegen, in der ersten Zeile den Ordner, z. B. H:\Web


3. MySQL Workbench
------------------

Workbench ist auf den Schul-PCs installiert und kann statt phpMyAdmin
genutzt werden. Erst START.bat, dann in Workbench einmal eine Verbindung
anlegen (Plus-Zeichen neben "MySQL Connections"):

  Connection Name:  SQL-Labor
  Hostname:         127.0.0.1
  Port:             13306          (nicht 3306)
  Username:         sus
  Password:         sus            (Store in Vault ...)

Die Warnung "Incompatible/nonstandard server version" mit "Continue
Anyway" bestätigen: Das SQL-Labor ist MariaDB, kein MySQL. Abfragen,
DML, DDL, Fremdschlüssel und Transaktionen gehen wie gewohnt; einzelne
Workbench-Funktionen für die MySQL-Verwaltung können fehlen.


4. Wenn etwas klemmt
--------------------

START.bat prüft den Datenordner selbst:
- War der erste Start abgebrochen (Ordner ohne Unterordner mysql), legt
  START.bat den Ordner beiseite und die Datenbank neu an.
- Startet der Server nicht (z. B. beschädigte Dateien nach hartem
  Ausschalten), zeigt START.bat die Meldungen des Servers und fragt, ob
  die Datenbank neu angelegt werden soll. Der alte Stand wird nicht
  gelöscht, sondern in data-defekt-DATUM-UHRZEIT umbenannt.
- MyISAM-Tabellen (northwind) repariert der Server beim Öffnen selbst.

Hilft das nicht: TEST.bat ausführen und testprotokoll.txt der Lehrkraft
zeigen.


5. Wo die Daten liegen
----------------------

Standard: %LOCALAPPDATA%\SQL-Labor (lokale Platte C:, schnell).
Anderer Ort: eine Datei DATENORT.txt neben START.bat anlegen, in der
ersten Zeile den Ordner, z. B.  H:\SQL-Labor   oder   D:\SQL-Labor-Daten
Ob ein Ort taugt, zeigt TEST.bat (Abschnitt 4).
Im Datenordner liegen auch server.err (Meldungen des Servers),
install.log, tmp (Cache von phpMyAdmin), sessions und dateien.

dateien ist der einzige Ordner, aus dem die Datenbank per SQL lesen und in
den sie schreiben darf (LOAD DATA INFILE, SELECT ... INTO OUTFILE), z. B.
für einen CSV-Import. START.bat zeigt den genauen Pfad an.


6. Test an einem Schul-PC (Lehrkraft, ca. 5 Minuten)
----------------------------------------------------

1. Zip auf den Schul-PC holen. Wurde sie aus dem Internet oder Moodle
   geladen: Rechtsklick auf die Zip, Eigenschaften, Haken bei "Zulassen",
   OK. Erst dann entpacken.
2. Ordner SQL-Labor dorthin entpacken, wo die SuS ihn später nutzen
   würden (lokales Laufwerk, Home-Laufwerk H: oder Tauschlaufwerk).
3. TEST.bat doppelklicken. Der Test dauert etwa 1-2 Minuten und prüft:
   - ob die Programme starten dürfen (AppLocker, SmartScreen),
   - ob PHP mit mysqli läuft,
   - ob die Datenbank auf der lokalen Platte, im Kit-Ordner und im
     Home-Laufwerk arbeitet (InnoDB schreiben und lesen),
   - ob der Webserver antwortet und fremde Host-Namen abweist,
   - ob der Webserver für eigene Seiten läuft und der Webordner
     angelegt werden kann.
4. Notieren, ob eine Windows-Sicherheitswarnung kam (Firewall,
   "Der Computer wurde durch Windows geschützt").
5. testprotokoll.txt mitbringen. Sie liegt im Kit-Ordner oder, wenn der
   schreibgeschützt ist, im Benutzerprofil (testprotokoll-sql-labor.txt).


7. Technik
----------

Ports:        13306 (MariaDB), 18080 (phpMyAdmin), 18000 (eigene Seiten),
              alle nur 127.0.0.1; TEST.bat nutzt zusätzlich 13307, 18081
              und 18082.
Schutz:       app\router.php beantwortet nur Anfragen an 127.0.0.1 oder
              localhost (gegen fremde Webseiten per DNS-Rebinding);
              Dateizugriffe per SQL nur im Ordner dateien; keine
              Server-Plugins. Mehr in SECURITY.md im Repo.
Benutzer:     sus / Passwort sus, Anmeldeverfahren mysql_native_password
              (für Workbench), nur lokal, alle Rechte, auch CREATE USER
              und GRANT.
Bestandteile: app\mariadb     MariaDB @MARIADB_VERSION@ winx64 (gekürzt: Server,
                              Client, mariadb-admin, mariadb-dump,
                              mariadb-install-db, mysqld.exe für
                              dessen Bootstrap)
              app\php         PHP @PHP_VERSION@ NTS x64 (gekürzt: php.exe, mysqli,
                              pdo_mysql, mbstring, fileinfo),
                              Visual-C++-Laufzeit aus dem MariaDB-Paket
              app\web-vorlage Startdateien für den Webordner
              app\phpmyadmin  phpMyAdmin @PMA_VERSION@ (nur Deutsch), angemeldet
                              über config.inc.php, Konfigurationsspeicher
                              in der Datenbank phpmyadmin
              app\sql         northwind.sql, init.sql (Benutzer)
